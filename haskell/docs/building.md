# Building & releasing

## Turnkey: `./bootstrap.sh`

From the repo root, `bootstrap.sh` installs the pinned `ae` (0.946.0) and `aeb`
via their official installers to a user prefix (`$HOME/.local`, no sudo; needs
`curl`) if they are missing, then runs `aeb` on the leaf you name:

```sh
./bootstrap.sh haskell/.tests.ae     # builds libservirtium_vcr, then runs `cabal test`
```

It does not install GHC or cabal (use [ghcup](https://www.haskell.org/ghcup/)). Override `PREFIX` / `AETHER_REF` / `AEB_REF` / `MIN_AE` via env.

Everything from here down is what that leaf automates.

## Prerequisites

- **GHC 9.6.x + cabal 3.10+** (this repo is developed against GHC 9.6.6 /
  cabal 3.10.3.0). `bootstrap.sh` does not install them.
- **The Aether toolchain (`ae`) on PATH** — only needed to build the *native*
  library; `bootstrap.sh` installs it via aether's `get.sh` if absent
  (`curl -sSL https://raw.githubusercontent.com/aether-lang-dev/aether/main/get.sh | sh`).

## Build the native library

The native library is built from the in-repo Aether VCR embedding module,
`core/embed.ae` (which imports the VCR itself, `core/vcr.ae`):

```sh
aeb core/.build.ae      # from the repo root
```

This produces the **host platform's** library into `core/native/`. The VCR source
lives in this repo (`core/`), so no Aether source checkout is needed — only the
`ae` toolchain on PATH to compile it. Under the hood:

```sh
ae build --emit=lib --with=fs,net,extern core/embed.ae \
   -o core/native/libservirtium_vcr.<ext>
```

- `--emit=lib` produces a shared library with `aether_*` exports.
- `--with=fs,net,extern` grants `extern` (required since ae 0.801: libservirtium_vcr declares C externs) plus the filesystem + networking capabilities the VCR
  needs (tape I/O + the embedded HTTP server). This requires a `-fPIC` Aether
  runtime, and the whole-tape normalization passes use `std.regex` — together
  these need **Aether 0.946.0**.

`aeb haskell/.tests.ae` also **generates `haskell/cabal.project.local`** with the
absolute `core/native/` dir and an rpath (see below). The native lib and
`cabal.project.local` are **git-ignored build artifacts**.

## Linking & loading (how the FFI lib is wired in)

Haskell's `foreign import ccall` statically links against the named shared
library. The `.cabal` declares `extra-libraries: servirtium_vcr` on **both**
the library and the test-suite.

`ghc-pkg` rejects a *relative* `extra-lib-dirs` when registering the library,
so the lib **directory** is supplied as an **absolute path** via
`cabal.project.local` (generated by `haskell/.tests.ae`), together with an rpath
so test binaries load libservirtium_vcr at run time without `LD_LIBRARY_PATH`:

```
package servirtium
  extra-lib-dirs: <abs>/core/native
  ghc-options: -optl-Wl,-rpath,<abs>/core/native
```

Verify both linker and loader resolve it:

```sh
readelf -d "$(cabal list-bin servirtium-test)" | grep -i runpath   # RUNPATH -> native/
ldd      "$(cabal list-bin servirtium-test)" | grep servirtium     # resolves the .so
```

## Build & test

```sh
cabal build all
cabal test          # rpath makes this work with no LD_LIBRARY_PATH
```

If you build the lib without the rpath, run
`LD_LIBRARY_PATH=<repo>/core/native cabal test`. To iterate on `core/embed.ae`,
rebuild with `aeb haskell/.tests.ae` from the repo root (it rebuilds
`core/native/` and regenerates `cabal.project.local`).

## Supply-chain notes

- Native builds are reproducible from `core/embed.ae` + a pinned Aether toolchain
  version — record the `ae --version` used so a hash can be verified from
  source.
- The native `.so` is a discrete file (not embedded in the Haskell objects),
  so it stays visible to SCA/SBOM tooling and is individually signable.
