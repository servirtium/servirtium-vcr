# Building & releasing

## Turnkey: `./bootstrap.sh`

For a casual dev, the repo-root `bootstrap.sh` encodes the steps below as one
idempotent command:

```sh
./bootstrap.sh        # extra args pass through to `cabal test`
```

It checks for `ae` (≥ 0.227.0) and installs it via aether's official `get.sh`
remote installer to a user prefix (`$HOME/.local` — **no sudo, no Aether test
suite, no contrib**; needs `curl`, no build-from-source fallback) if it's
missing/too old; checks GHC + cabal are present (it does **not** auto-install
them — use [ghcup](https://www.haskell.org/ghcup/)); then runs
`build-native.sh` and `cabal test`. It exports
`LD_LIBRARY_PATH=$PWD/native` for the test run as a fallback (the rpath baked
by `build-native.sh` already covers loading). On failure it prints the
`-fPIC` re-install triage. Override `PREFIX` / `AETHER_REF` (pin in CI) /
`MIN_AE` via env.

Everything from here down is what `bootstrap.sh` automates — useful when you
already have all three toolchains.

## Prerequisites

- **GHC 9.6.x + cabal 3.10+** (this repo is developed against GHC 9.6.6 /
  cabal 3.10.3.0). `bootstrap.sh` checks for them but does not install them.
- **The Aether toolchain (`ae`) on PATH** — only needed to build the *native*
  library; `bootstrap.sh` installs it via aether's `get.sh` if absent
  (`curl -sSL https://raw.githubusercontent.com/aether-lang-org/aether/main/get.sh | sh`).

## Build the native library

The native library is built from the in-repo Aether VCR embedding module,
`core/embed.ae` (which imports the VCR itself, `core/vcr.ae`):

```sh
./build-native.sh
```

This produces the **host platform's** library into `native/`. The VCR source
lives in this repo (`core/`), so no Aether source checkout is needed — only the
`ae` toolchain on PATH to compile it. Under the hood:

```sh
ae build --emit=lib --with=fs,net core/embed.ae \
   -o native/libservirtium_vcr.<ext>
```

- `--emit=lib` produces a shared library with `aether_*` exports.
- `--with=fs,net` grants the filesystem + networking capabilities the VCR
  needs (tape I/O + the embedded HTTP server). This requires a `-fPIC` Aether
  runtime, and the whole-tape normalization passes use `std.regex` — together
  these need **Aether ≥ 0.227.0**.

`build-native.sh` also **generates `cabal.project.local`** with the absolute
`native/` dir and an rpath (see below). The native lib and
`cabal.project.local` are **git-ignored build artifacts** — run
`build-native.sh` after cloning.

## Linking & loading (how the FFI lib is wired in)

Haskell's `foreign import ccall` statically links against the named shared
library. The `.cabal` declares `extra-libraries: servirtium_vcr` on **both**
the library and the test-suite.

`ghc-pkg` rejects a *relative* `extra-lib-dirs` when registering the library,
so the lib **directory** is supplied as an **absolute path** via
`cabal.project.local` (generated by `build-native.sh`), together with an rpath
so test binaries load the engine at run time without `LD_LIBRARY_PATH`:

```
package servirtium-haskell
  extra-lib-dirs: <abs>/native
  ghc-options: -optl-Wl,-rpath,<abs>/native
```

Verify both linker and loader resolve it:

```sh
readelf -d "$(cabal list-bin servirtium-haskell-test)" | grep -i runpath   # RUNPATH -> native/
ldd      "$(cabal list-bin servirtium-haskell-test)" | grep servirtium     # resolves the .so
```

## Build & test

```sh
cabal build all
cabal test          # rpath makes this work with no LD_LIBRARY_PATH
```

If you build the lib without the rpath, run
`LD_LIBRARY_PATH=$PWD/native cabal test`. To iterate on `core/embed.ae`, rebuild
with `./build-native.sh` (it overwrites `native/` and regenerates
`cabal.project.local`).

## Supply-chain notes

- Native builds are reproducible from `core/embed.ae` + a pinned Aether toolchain
  version — record the `ae --version` used so a hash can be verified from
  source.
- The native `.so` is a discrete file (not embedded in the Haskell objects),
  so it stays visible to SCA/SBOM tooling and is individually signable.
